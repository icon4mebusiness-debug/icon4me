# Icon4U

אפליקציית מעקב אימונים לשני משתמשים — יונתן ואיתמר.
בכניסה הראשונה המכשיר שואל במי מדובר, וזוכר את הבחירה. מסך הבית מציג "שלום" עם השם,
ומתחתיו כפתור לכל סוג אימון, כפתור התקדמות עם לוח חודשי, וכפתור יומן.

הכל עובד גם בלי אינטרנט: הנתונים נשמרים במכשיר, ומסתנכרנים ל‑Supabase כשהוא זמין.

---

## הקבצים

| קובץ | מה זה |
|---|---|
| `index.html` | כל האפליקציה — עיצוב, לוגיקה ותוכניות האימון |
| `config.js` | כתובת ומפתח Supabase. זה הקובץ היחיד שצריך לערוך |
| `schema.sql` | מסד הנתונים: טבלאות, אינדקסים, הרשאות ותוכניות האימון ההתחלתיות |
| `manifest.webmanifest` + `icon-192.png` | מאפשרים "הוסף למסך הבית" באייפון ובאנדרואיד |

## שלב 1 — Supabase

1. פותחים פרויקט חדש ב‑[supabase.com](https://supabase.com) (התוכנית החינמית מספיקה בגדול).
2. נכנסים ל‑**SQL Editor → New query**, מדביקים את כל התוכן של `schema.sql`, ומריצים (Run).
   זה יוצר את כל הטבלאות וגם מזין את שתי התוכניות — כל התרגילים, היעדים ודגשי הטכניקה.
3. נכנסים ל‑**Settings → API** ומעתיקים שני דברים: `Project URL` ו‑`anon public`.
4. פותחים את `config.js` ומדביקים אותם:

```js
window.SUPABASE_URL      = 'https://xxxxxxxx.supabase.co';
window.SUPABASE_ANON_KEY = 'eyJhbGciOi...';
```

אם לא ממלאים — האפליקציה עדיין עובדת, פשוט שומרת רק על המכשיר.

### על ההרשאות

לאפליקציה אין מסך התחברות, ושני הטלפונים משתמשים באותו מפתח ציבורי. לכן `schema.sql`
פותח את הטבלאות האלה למפתח ה‑anon. מבחינה מעשית: מי שמגיע לכתובת האתר ופותח את קוד המקור
יכול לקרוא ולכתוב לטבלאות האלה. לאפליקציה משפחתית זה בדרך כלל בסדר, אבל כדאי לדעת.

שתי דרכים פשוטות להדק, אם בא לך:

- **Cloudflare Access** — שמים את האתר מאחורי דף התחברות עם רשימת מיילים מורשית. ההגנה
  קורית לפני שהדפדפן בכלל טוען את הדף, ולא צריך לגעת בקוד.
- **Supabase Auth** — הוספת התחברות אמיתית והחלפת ה‑policies ב‑`schema.sql` בתנאי
  `auth.uid()`. זה הפתרון הנכון יותר, אבל מוסיף חיכוך של התחברות בכל מכשיר.

## שלב 2 — GitHub

```bash
cd icon4u-app
git init
git add .
git commit -m "Icon4U"
git branch -M main
git remote add origin https://github.com/<המשתמש-שלך>/icon4u.git
git push -u origin main
```

שים לב ש‑`config.js` מכיל את מפתח ה‑anon. הוא נועד להיות ציבורי (הוא נשלח לכל דפדפן
שטוען את האתר), אבל אם הריפו ציבורי — זה אומר שהמפתח גלוי לכולם. אם זה מפריע, עדיף
ריפו פרטי, ולוודא שהמפתח שהעתקת הוא `anon public` ולא `service_role`. את
`service_role` אף פעם לא שמים בקוד צד‑לקוח.

## שלב 3 — Cloudflare Pages

1. ב‑Cloudflare Dashboard: **Workers & Pages → Create → Pages → Connect to Git**,
   ובוחרים את הריפו.
2. בהגדרות הבנייה:
   - Framework preset: **None**
   - Build command: להשאיר ריק
   - Build output directory: `/` (או `icon4u-app` אם העלית את התיקייה כתת‑תיקייה)
3. Deploy. תוך פחות מדקה מקבלים כתובת כמו `icon4u.pages.dev`.

כל `git push` יעדכן את האתר אוטומטית.

### התקנה בטלפון

פותחים את הכתובת בטלפון → בספארי "שתף → הוסף למסך הבית", בכרום "התקן אפליקציה".
מכאן זה נפתח במסך מלא, בלי שורת כתובת, ונראה כמו אפליקציה רגילה.

## מבנה מסד הנתונים

| טבלה | תפקיד |
|---|---|
| `profiles` | יונתן ואיתמר — שם, צבע, מטרה, יעד אימונים שבועי |
| `programs` | סוגי האימון של כל אחד (חדר כושר / ביתי / אירובי, או A‑B‑C‑D) |
| `exercises` | קטלוג התרגילים: יעד סטים וחזרות, קפיצת משקל, שריר עיקרי ודגשי טכניקה |
| `exercise_state` | **משקל העבודה הנוכחי לכל תרגיל** — זה מה שגורם לאפליקציה לזכור מה שמתם |
| `workouts` | כותרת אימון: מי, מתי, איזו תוכנית, והערה |
| `workout_sets` | שורה לכל סט: משקל, חזרות, והאם סומן כבוצע |
| `cardio_state` / `cardio_log` | השלב הנוכחי בריצה/אופניים, ורישום כל אימון אירובי |
| `daily_log` | צעדים ומשקל גוף לפי תאריך |

בנוסף שני views מוכנים לשאילתות:

- `v_training_days` — יום אימון אחד לכל שורה. זה מה שמזין את הלוח החודשי.
- `v_exercise_progress` — 1RM משוער ומשקל שיא לכל תרגיל לאורך זמן.

דוגמה — כמה ימי אימון היו בכל חודש:

```sql
select profile_id, date_trunc('month', date) as month, count(distinct date) as training_days
from v_training_days
group by 1, 2
order by 2 desc;
```

## שינוי תוכניות האימון

התרגילים יושבים בשני מקומות: בקטלוג ש‑`schema.sql` מזין לטבלת `exercises`, וכעותק
בתוך `index.html` (כדי שהאפליקציה תעבוד גם בלי רשת). כרגע האפליקציה קוראת את התרגילים
מ‑`index.html` ואת המשקלים מ‑Supabase.

להוספת תרגיל: מוסיפים אותו בשני המקומות עם אותו `ex_key` (הפורמט הוא
`<תוכנית>-<מספר סידורי דו‑ספרתי>`, למשל `gym-09`). המפתח הזה הוא מה שמקשר בין
התרגיל, המשקל השמור וההיסטוריה — אז אסור לשנות מפתח של תרגיל קיים, אחרת ההיסטוריה
שלו תתנתק.
