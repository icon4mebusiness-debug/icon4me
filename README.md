# icon4me

אפליקציית מעקב אימונים לשני משתמשים — יונתן ואיתמר.
בכניסה הראשונה המכשיר שואל במי מדובר וזוכר את הבחירה. מסך הבית מציג "שלום" עם השם,
ומתחתיו כפתור לכל סוג אימון, כפתור התקדמות עם לוח חודשי, וכפתור יומן.

הנתונים נשמרים במכשיר, ומסתנכרנים ל‑Supabase כשהוא מוגדר וזמין.

---

## הקבצים

| קובץ | מה זה |
|---|---|
| `index.html` | כל האפליקציה — עיצוב, לוגיקה ותוכניות האימון |
| `config.js` | כתובת ומפתח Supabase. זה הקובץ היחיד שצריך לערוך |
| `sw.js` | Service worker — מה שגורם לאפליקציה להיפתח גם בלי רשת |
| `manifest.webmanifest` | שם, צבעים ואייקונים להתקנה על מסך הבית |
| `schema.sql` | מסד הנתונים: טבלאות, אינדקסים, הרשאות ותוכניות האימון ההתחלתיות |
| `apple-touch-icon.png` | האייקון שאייפון משתמש בו (180×180) |
| `icon-192.png`, `icon-512.png` | אייקונים לאנדרואיד ולדפדפן |
| `icon-512-maskable.png` | גרסה לאנדרואיד, שמאפשרת חיתוך לצורות שונות |
| `favicon-32.png` | האייקון בטאב של הדפדפן |

**כל הקבצים חייבים לשבת באותה תיקייה.** האפליקציה מחפשת אותם לפי שם, ושמות הקבצים
רשומים גם ב‑`manifest.webmanifest` וגם ב‑`sw.js` — אם משנים שם קובץ, צריך לעדכן בשלושתם.

## שלב 1 — העלאה לאוויר

זה השלב היחיד שבאמת חייבים. בלעדיו הדפדפן חוסם את השמירה, כי קובץ שנפתח
ישירות מהמכשיר (`file://`) נחשב סביבה לא בטוחה.

- **Netlify** — גוררים את התיקייה ל‑Netlify Drop, או מחברים ריפו מגיטהאב.
  Build command: להשאיר ריק. Publish directory: התיקייה שבה יושב `index.html`.
- **Cloudflare Pages** — Workers & Pages → Create → Pages → Connect to Git.
  Framework preset: None. Build command: ריק.

בשתי האפשרויות מקבלים כתובת `https` תוך פחות מדקה, וכל עדכון בריפו מתפרסם לבד.

## שלב 2 — Supabase (אופציונלי)

בלי השלב הזה האפליקציה עובדת במלואה — פשוט כל מכשיר שומר לעצמו, בלי סנכרון בין הטלפונים.

1. פותחים פרויקט חדש ב‑[supabase.com](https://supabase.com) (התוכנית החינמית מספיקה בגדול).
2. נכנסים ל‑**SQL Editor → New query**, מדביקים את כל התוכן של `schema.sql`, ומריצים (Run).
3. נכנסים ל‑**Settings → API** ומעתיקים `Project URL` ו‑`anon public`.
4. מדביקים אותם ב‑`config.js`:

```js
window.SUPABASE_URL      = 'https://xxxxxxxx.supabase.co';
window.SUPABASE_ANON_KEY = 'eyJhbGciOi...';
```

### על ההרשאות

לאפליקציה אין מסך התחברות, ושני הטלפונים משתמשים באותו מפתח ציבורי. לכן `schema.sql`
פותח את הטבלאות למפתח ה‑anon: מי שמגיע לכתובת ופותח את קוד המקור יכול לקרוא ולכתוב.
לאפליקציה משפחתית זה בדרך כלל בסדר, אבל כדאי לדעת. שתי דרכים להדק:

- **Cloudflare Access** — דף התחברות לפני האתר, עם רשימת מיילים מורשית. לא נוגעים בקוד.
- **Supabase Auth** — התחברות אמיתית והחלפת ה‑policies בתנאי `auth.uid()`. נכון יותר,
  אבל מוסיף חיכוך בכל מכשיר.

את `service_role` אף פעם לא שמים בקוד צד‑לקוח. אם הריפו ציבורי, גם מפתח ה‑anon גלוי —
עדיף ריפו פרטי.

## התקנה בטלפון

**אייפון:** פותחים את הכתובת ב‑**ספארי** (חשוב — בכרום באייפון אין "הוסף למסך הבית"),
לוחצים על כפתור השיתוף ואז "הוסף למסך הבית". האפליקציה תיפתח במסך מלא, בלי שורת כתובת.

**אנדרואיד:** בכרום, תפריט → "התקן אפליקציה".

אחרי ההתקנה הראשונה ה‑service worker שומר עותק מקומי, ומהפעם השנייה האפליקציה
נפתחת מיידית וגם בלי רשת.

### מה שכדאי לדעת על אייפון

- **החלפת אייקון לא מתעדכנת לבד.** אם כבר הוספת את האפליקציה למסך הבית, צריך למחוק
  אותה ולהוסיף מחדש כדי לראות אייקון חדש.
- **iOS מוחק אחסון של אתרים שלא ביקרת בהם 7 ימים.** לאפליקציה שהותקנה למסך הבית זה
  בדרך כלל לא קורה, אבל זו סיבה טובה להגדיר את Supabase, או לייצא גיבוי מדי פעם
  מתוך היומן.
- כל הנתונים נשמרים לפי הכתובת. אם תעלה מחדש לכתובת אחרת, ההיסטוריה לא תעבור.

## מבנה מסד הנתונים

| טבלה | תפקיד |
|---|---|
| `profiles` | יונתן ואיתמר — שם, צבע, מטרה, יעד אימונים שבועי |
| `programs` | סוגי האימון של כל אחד |
| `exercises` | קטלוג התרגילים: יעד סטים וחזרות, קפיצת משקל, שריר עיקרי ודגשי טכניקה |
| `exercise_state` | **משקל העבודה הנוכחי לכל תרגיל** — זה מה שגורם לאפליקציה לזכור מה שמתם |
| `workouts` | כותרת אימון: מי, מתי, איזו תוכנית, והערה |
| `workout_sets` | שורה לכל סט: משקל, חזרות, והאם סומן כבוצע |
| `cardio_state` / `cardio_log` | רישום כל אימון אירובי או משחק |
| `daily_log` | צעדים ומשקל גוף לפי תאריך |

שני views מוכנים: `v_training_days` (יום אימון לכל שורה, מזין את הלוח החודשי)
ו‑`v_exercise_progress` (1RM משוער ומשקל שיא לכל תרגיל).

## מסך האירובי

חמש פעילויות: ריצה, אופניים, כדורגל, כדורסל, טניס. רושמים זמן בלבד; בריצה ובאופניים
יש גם שדה מרחק, ואם מילאת אותו יופיע גרף קצב. אין שלבים ואין דירוג מאמץ.

הפעילויות מוגדרות ב‑`index.html` במערך `CARDIO_KINDS`. להוספת ספורט חדש מוסיפים שורה
עם `id` באנגלית, `label`, `icon`, ו‑`km: true` רק אם המרחק רלוונטי. אין צורך לגעת
ב‑`schema.sql` — טבלת `cardio_log` מקבלת כל ערך.

## שינוי תוכניות האימון

התרגילים יושבים בשני מקומות: בקטלוג ש‑`schema.sql` מזין לטבלת `exercises`, וכעותק
בתוך `index.html` (כדי שהאפליקציה תעבוד גם בלי רשת). האפליקציה קוראת את התרגילים
מ‑`index.html` ואת המשקלים מ‑Supabase.

להוספת תרגיל מוסיפים אותו בשני המקומות עם אותו `ex_key` (הפורמט הוא
`<תוכנית>-<מספר סידורי דו‑ספרתי>`, למשל `gym-09`). המפתח מקשר בין התרגיל, המשקל
השמור וההיסטוריה — **אסור לשנות מפתח של תרגיל קיים**, אחרת ההיסטוריה שלו תתנתק.

השרירים בהדמיה נבחרים בשדה `hl` של כל תרגיל. הערכים האפשריים: `chest`, `lats`,
`traps`, `shoulders`, `biceps`, `triceps`, `forearms`, `abs`, `obliques`,
`lowerBack`, `glutes`, `quads`, `hamstrings`, `calves`.
